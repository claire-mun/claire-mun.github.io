DSH Desktop: 데스크톱 자체를 플러그인으로 취급하는 DeepSeek Harness 클라이언트

2026년 09월 01일 · 출처 4곳

DeepSeek Harness의 로컬 Web UI, Host 서비스, 플러그인 시스템을 Windows·macOS 네이티브 앱으로 감싼 MIT 라이선스 TypeScript 프로젝트입니다. 데스크톱 셸을 확장 가능한 런타임으로 설계한 사례를 보려는 엔지니어, 그리고 DSH 플러그인을 직접 만들 사람에게 의미가 있습니다.

01이게 무엇인가

저장소 설명은 이 프로젝트를 "DeepSeek Harness(DSH) 플러그인 생태계를 위한 데스크톱 솔루션"으로 규정하면서, 만물이 플러그인이고 데스크톱 자체도 플러그인이라고 못박습니다. 이 문장은 마케팅 카피가 아니라 아키텍처 선언에 가깝습니다. 앱을 먼저 만들고 확장점을 나중에 뚫은 구조가 아니라, 창·트레이·터미널 같은 셸 기능부터가 플러그인 계약 위에 올라가 있다는 뜻입니다.

README는 역할 분담을 명확히 나눕니다. DeepSeek Harness 상류가 로컬 Web UI와 Host 서비스, 플러그인 메커니즘을 제공하고, DSH Desktop은 창, 트레이, 터미널, 업데이트, 작업 설정을 제공합니다. 그리고 상류의 특정 버전을 고정해 원본 그대로 실행한다고 적혀 있습니다. 즉 이 저장소는 DSH를 포크해 개조한 결과물이 아니라, 고정된 상류를 감싸고 그 위에 플러그인을 얹는 계층입니다.

소속 관계도 README 상단에서 먼저 밝히고 갑니다. 독립적인 커뮤니티 오픈소스 프로젝트이며 深度求索(DeepSeek)와 종속·협력·라이선스·보증 관계가 없다고 명시합니다.

03어떻게 구성돼 있나

추적 파일은 866개입니다. 가장 큰 덩어리는 dsh-plugin-desktop/ 아래 312개로, 이름 그대로 데스크톱 기능 자체가 하나의 플러그인 패키지에 모여 있습니다. 그다음이 vendor/ 242개, dsh-community-market/ 107개, .agents/ 69개입니다.

파일 종류 분포는 이 구조를 다시 확인해 줍니다. .ts가 297개, .tgz가 241개, .md가 110개, .yaml이 45개입니다. .tgz 241개와 vendor/ 242개가 거의 겹친다는 점이 눈에 띕니다. vendor/ 디렉터리가 사실상 npm 타르볼 보관소라는 뜻이고, 의존성이 레지스트리 참조가 아니라 저장소 안에 통째로 들어와 있다는 의미입니다. 상류 버전을 고정해 원본 그대로 실행한다는 README의 서술과 같은 방향의 선택입니다. .md 110개는 문서량이 코드 대비 적지 않다는 뜻이고, .yaml 45개와 .agents/ 69개는 에이전트·워크플로 설정이 별도 계층으로 분리돼 있음을 시사합니다.

플러그인 계약이 어떻게 생겼는지는 dsh-community-market/src/client/index.ts에서 드러납니다. 이 파일은 @deepseek-ai/cordis의 Context를 받고, inject = ['slots', 'locale']로 필요한 서비스를 선언한 뒤 apply(ctx) 안에서 등록 작업을 합니다. ctx.locale.register로 zh/en 사전을 붙이고, ctx.slots.inject('settings.plugins.tab', ...)와 sidebar.footer.action으로 기존 UI의 지정된 자리에 컴포넌트를 꽂습니다. 주목할 부분은 dsh-client-ui-conversation, dsh-client-ui-layout, dsh-client-ui-sidebar 같은 형제 패키지들을 전부 `import type {}` 형태로만 가져온다는 점입니다. 런타임 의존이 아니라 타입 선언 병합용이고, 실제 런타임 의존성은 inject 배열로만 표현됩니다. UI 슬롯 이름과 order 값으로 결합하는 방식이라 플러그인끼리 서로를 직접 호출하지 않습니다.

04실제로 어떻게 쓰는가

정식 설치 패키지는 Windows x64와 macOS Universal 두 가지입니다. Windows는 NSIS 설치 프로그램을 실행하고, macOS는 DMG를 열어 DSH Desktop을 Applications로 끌어다 놓습니다. 자세한 절차와 플러그인 명령, 문제 해결은 docs/user-guide.md와 docs/faq.md에 정리돼 있습니다.

플러그인을 만드는 쪽이라면 위의 index.ts가 사실상 템플릿입니다. NS 상수로 로케일 네임스페이스를 잡고, declare module로 LocaleNamespaceMap에 키 타입을 확장하고, inject로 의존 서비스를 선언한 뒤 apply에서 슬롯에 등록하는 순서입니다. ctx.effect로 스타일 설치와 사전 등록을 감싸 두어 정리(cleanup) 경로를 런타임에 맡기는 형태도 그대로 따라갈 만합니다.

생태계 방향은 docs/plugin-ecosystem.md의 "DSH 플러그인 생태계 제안서"에 별도로 적혀 있고, Discord 채널도 README에 링크돼 있습니다.

05무엇을 못 하는가, 어디를 조심해야 하나

먼저 소속 문제입니다. README는 이 저장소에 DeepSeek 직원이나 DeepSeek Harness 상류 공식 팀 구성원이 참여하고 있지 않으며, GitHub Contributors에 보이는 상류 기여자는 포크로 상속되고 동기화된 커밋 이력에서 온 것이라고 직접 밝힙니다. 컨트리뷰터 목록을 보고 공식 프로젝트로 오해하기 쉬운 지점을 프로젝트 쪽에서 먼저 차단해 둔 셈인데, 뒤집어 말하면 상류 지원을 기대할 수 없다는 뜻이기도 합니다.

버전 고정도 양면입니다. 상류의 특정 버전을 고정해 원본 그대로 실행하므로 동작은 예측 가능하지만, 상류의 수정이나 신규 기능은 이 저장소가 고정 버전을 올릴 때까지 반영되지 않습니다. vendor/ 아래 241개의 .tgz도 같은 성격입니다. 재현성은 좋아지지만 의존성 갱신이 커밋 단위 작업이 되고, 저장소에 들어온 타르볼은 외부에서 갱신되지 않습니다.

플랫폼은 Windows x64와 macOS Universal 두 가지만 정식 패키지로 제공됩니다. 그 밖의 환경은 README의 설치 표에 없습니다. 마지막으로 README 배지의 링크 대상이 anywhere-labs/deepseek-harness-desktop 경로를 가리키고 있어 저장소 경로와 다릅니다. 릴리스와 다운로드 수를 확인할 때는 어느 경로를 보고 있는지 확인하는 편이 낫습니다.
