상류를 고정해 감싼 껍데기

저장소 설명은 DSH 플러그인 생태계를 위한 데스크톱 솔루션이라고 말하고, 모든 것이 플러그인이며 데스크톱 자신도 플러그인이라고 덧붙입니다. README를 열면 범위가 훨씬 좁아집니다. DSH Desktop은 DeepSeek Harness의 로컬 Web UI, Host 서비스, 플러그인 시스템을 네이티브 데스크톱 앱 안으로 통합하고, 특정 상류 버전을 고정해 그대로 실행합니다. 이 프로젝트가 직접 제공한다고 밝힌 것은 창, 트레이, 터미널, 업데이트, 작업 설정입니다. 나머지 기능은 상류가 제공하는 플러그인 메커니즘을 통해 조합됩니다.

README 상단의 작은 글씨가 더 많은 것을 말합니다. 독립적인 커뮤니티 오픈소스 프로젝트이며 딥시크와 소속, 협력, 인가, 보증 관계가 없다고 못을 박고, 현재 이 저장소에는 딥시크 직원도 DeepSeek Harness 상류 공식 팀 구성원도 참여하지 않으며 GitHub Contributors에 보이는 상류 기여자는 fork 상속과 동기화된 커밋 이력에서 온 것이라고 설명합니다. 즉 기여자 목록을 신뢰의 근거로 읽으면 안 된다는 경고입니다.

주소도 한 겹 어긋나 있습니다. 이 저장소의 경로는 anywhere-labs/dsh-desktop인데, README에 박힌 release, downloads, stars 배지와 최신 릴리스 링크는 모두 anywhere-labs/deepseek-harness-desktop을 가리킵니다. 여기 기록된 스타 23456과 배지가 세는 숫자가 같은 곳에서 나온다는 보장은 없습니다.

beta와 stable, 그리고 tgz

추적 파일은 1212개입니다. 그중 dsh-plugin-desktop-beta/ 아래가 328개, dsh-plugin-desktop/ 아래가 325개입니다. 앱 셸이 아니라 이름이 한 단어만 다른 두 디렉터리가 저장소 부피의 중심입니다. 크기가 이 정도로 비슷하다는 것은 한쪽이 다른 쪽의 축약본이 아니라, 같은 플러그인의 안정판과 베타판을 통째로 병행 유지하고 있다는 뜻입니다. 어느 쪽을 따라갈지는 저장소를 쓰는 쪽의 선택으로 남습니다.

세 번째 덩어리는 vendor/의 243개입니다. 확장자별 집계에서 .tgz가 242개이고, 두 숫자를 나란히 놓으면 vendor/가 사실상 패키지 아카이브 보관소라는 그림이 나옵니다. 의존성을 레지스트리에서 당겨오는 대신 압축된 형태로 트리 안에 넣어 두는 방식입니다. 빌드 재현성은 올라가고, 대신 무엇이 들어 있는지 확인하려면 아카이브를 풀어야 합니다.

확장자 분포도 예상과 다릅니다. .ts가 545개인데 .tsx는 71개입니다. 채팅 화면을 가진 데스크톱 클라이언트치고 컴포넌트 파일의 몫이 작습니다. 코드 대부분은 화면을 그리는 쪽이 아니라 Host와 플러그인을 엮는 쪽에 있습니다. .md 117개는 이중 언어 README와 사용자 가이드, FAQ, 플러그인 생태계 문서가 차지하는 몫입니다.

슬롯에 등록되는 단위

dsh-community-market/src/client/index.ts는 이 저장소의 코드 단위가 어떤 모양인지 그대로 보여줍니다. 이 파일은 index.ts라는 이름을 가진 8개 파일 중 하나입니다. 파일은 @deepseek-ai/cordis의 Context 타입을 들여오고, inject = ['slots', 'locale']을 내보낸 뒤 apply(ctx) 하나를 정의합니다. cordis 스타일의 플러그인 규약입니다. 필요한 서비스를 이름으로 선언하고, 런타임이 넣어 준 컨텍스트만 통해 바깥과 이야기합니다.

주목할 부분은 import 목록입니다. dsh-client-locale, dsh-client-ui-conversation, dsh-client-ui-layout, dsh-client-ui-renderer, dsh-client-ui-session, dsh-client-ui-settings, dsh-client-ui-sidebar, dsh-client-ui-workspace가 전부 import type {} 형태로만 들어옵니다. 값은 하나도 가져오지 않습니다. 이 패키지들은 컴파일 시점에 타입을 확장하기 위해서만 존재하고, 실제 연결은 ctx를 통해 이루어집니다. declare module으로 LocaleNamespaceMap에 'community-market' 키를 끼워 넣는 부분이 같은 원리입니다.

UI를 붙이는 방법도 컴포넌트를 직접 import해 트리에 꽂는 방식이 아닙니다. ctx.slots.inject('settings.plugins.tab', ...)처럼 슬롯 이름과 id, order 20, label, locale을 함께 등록하면 호스트가 그 자리를 채웁니다. 사이드바 하단 액션도 같은 경로로 들어갑니다. 스타일 설치와 사전 등록은 ctx.effect로 감싸 'community-market: styles' 같은 이름을 달아 두는데, 이는 플러그인이 내린 부수효과를 나중에 되돌릴 수 있도록 붙잡아 두는 장치입니다. 데스크톱 자신도 플러그인이라는 문구는 여기서 구체적인 뜻을 가집니다. 붙는 지점이 전부 슬롯 이름이라는 것.

설치 다음에 남는 선택

설치 자체는 짧습니다. 정식 설치 패키지는 Windows x64와 macOS Universal을 지원하고, 추가 환경 없이 다운로드해서 쓰라고 안내합니다. Windows는 NSIS 설치 프로그램을 실행하고, macOS는 DMG를 열어 Applications로 끌어다 놓습니다.

끝나지 않는 단계는 그다음입니다. 기능이 플러그인 단위로 쪼개져 있으니 어떤 플러그인을 넣을지가 남고, 플러그인 명령과 문제 해결은 별도 문서인 docs/user-guide.md와 docs/faq.md로 넘어갑니다. 플러그인을 고르는 화면인 커뮤니티 마켓조차 설정 탭에 자기 자신을 등록하는 플러그인입니다. 그리고 이 프로젝트는 상류 버전을 고정해 실행하므로, 상류에 새 기능이 생겨도 고정이 옮겨질 때 도착합니다.

좁은 쪽은 라이선스가 아니다

라이선스는 MIT라 도입을 막는 조건이 아닙니다. 좁은 쪽은 범위입니다. 정식 설치 패키지가 Windows x64와 macOS Universal 두 가지이고, 인용된 마켓 플러그인이 등록하는 사전도 zh와 en 둘입니다.

운영 비용은 세 곳에서 나옵니다. 열린 이슈는 314개이고 마지막 푸시는 2026-09-04로 움직임이 있는 저장소지만, README가 스스로 밝혔듯 상류 공식 팀은 참여하지 않으므로 문제가 생겼을 때 기댈 곳은 커뮤니티입니다. vendor/에 쌓인 아카이브는 의존성 감사를 트리 안으로 끌어들이고, beta와 stable 두 벌의 플러그인 디렉터리는 어느 쪽을 기준으로 검증할지를 매번 정하게 만듭니다.
