GLM-5.3 구조 뜯어보기: 베이스는 그대로, MoE에 붙은 DSA 인덱서와 141개 샤드

2026년 09월 01일 · 출처 3곳

zai-org/GLM-5.3은 GLM-5.2와 동일한 베이스 모델 위에서 post-training만으로 코딩·장기 과제 성능을 끌어올렸다고 밝힌 open-weights 모델입니다. transformers 기반으로 자체 아키텍처 클래스를 쓰는 대형 MoE를 실제로 서빙하거나 파인튜닝할지 검토하는 엔지니어를 위한 정리입니다.

01이 모델이 무엇인가

GLM-5.3은 Hugging Face에서 text-generation 태스크로 공개된 모델이며, 라이브러리는 transformers, 선언된 언어 태그는 en과 zh입니다. 모델 카드는 GLM-5.3이 GLM-5.2와 같은 베이스 모델을 쓰고 모든 개선이 post-training에서 나왔다고 명시합니다. 즉 사전학습 코퍼스나 파라미터 배치가 아니라 사후 학습 레시피의 차이를 파는 릴리스입니다.

아키텍처 클래스는 GlmMoeDsaForCausalLM, model_type은 glm_moe_dsa입니다. 이름 그대로 MoE(mixture of experts)와 DSA 계열의 희소 어텐션 인덱서가 결합된 구조이며, 표준 llama/qwen 계열 클래스가 아니라 전용 모델링 코드를 요구하는 형태입니다. 태그에는 conversational과 arxiv:2602.15763, eval-results가 함께 걸려 있어, 대화형 사용을 전제로 하고 별도 논문과 평가 결과가 연결돼 있음을 알 수 있습니다.

마지막 수정 시각은 2026-08-31T13:33:35.000Z입니다.

02지금 트렌딩에 오른 이유

수치상으로는 좋아요 1504, 최근 30일 다운로드 94403입니다. 관심의 근거는 모델 카드가 내세우는 두 축입니다. 첫째는 코딩으로, 자체 Z.ai Code Bench에서 GLM-5.2 대비 50% 향상을 주장하며 Terminal Bench 3.0과 Agents' Last Exam에서 open-source SOTA라고 밝힙니다. 둘째는 사이버 능력으로, 카드는 post-training을 확장하면서 예상보다 빠르게 발현했고 취약점 발견 벤치마크인 CyberGym에서 state of the art라고 설명합니다.

표를 보면 세대 간 격차가 특정 벤치마크에 몰려 있습니다. Terminal Bench 2.1은 GLM-5.3 88.2 대 GLM-5.2 81.0으로 완만하지만, Terminal Bench 3.0은 28.3 대 4.6, SWE-Marathon (v1.1)은 42.5 대 19.4, ProgramBench (Almost Solved)는 19.0 대 9.5로 벌어집니다. 포화된 벤치마크가 아니라 아직 여유가 남은 장기·에이전트형 과제에서 post-training 효과가 드러난다는 뜻입니다.

동시에 표는 이 모델이 모든 항목에서 1위가 아니라는 점도 그대로 보여줍니다. Terminal Bench 3.0은 GPT-5.6 Sol 34.6, DeepSWE (v1.1)도 GPT-5.6 Sol 72.7, NL2Repo는 Opus 4.8 69.7이 최고치로 표기돼 있습니다. CyberGym 84.5는 표에서 GLM-5.3이 굵게 표시된 항목입니다.

03실제로 무엇이 들어 있나

저장소 파일 수는 154개이고 그중 가중치 샤드가 141개입니다. dtype은 bfloat16으로 선언돼 있습니다. 샤드 수가 이 정도라면 다운로드와 로딩 자체가 스토리지·네트워크 계획의 대상이 되며, 단일 파일 기준으로 취급하는 파이프라인은 그대로 쓰기 어렵습니다.

config.json의 밀도 관련 값은 hidden_size 6144, intermediate_size 12288, head_dim 192, attention_bias false, hidden_act silu입니다. MoE 배치는 first_k_dense_replace 3으로, mlp_layer_types가 dense, dense, dense로 시작하는 것과 일치합니다. 즉 앞쪽 세 개 레이어만 dense이고 이후가 희소 레이어입니다. ep_size는 1로, 배포된 config 자체는 expert parallelism을 켠 상태가 아닙니다.

어텐션 쪽이 이 모델의 특징입니다. kv_lora_rank 512로 KV를 저차원으로 압축하고, 별도의 인덱서가 index_head_dim 128, index_n_heads 32, index_topk 2048로 정의돼 있습니다. index_topk_freq 4, index_skip_topk_offset 3, indexer_rope_interleave true, index_share_for_mtp_iteration true 같은 값들이 함께 붙어 있고, indexer_types 배열은 앞의 세 항목이 full, 이후 full 하나에 shared 세 개가 반복되는 주기 패턴입니다. 전체 레이어가 아니라 일부 레이어만 full 인덱서를 계산하고 나머지는 공유하는 구조로 읽힙니다.

max_position_embeddings는 1048576입니다. eos_token_id는 154820, 154827, 154829 세 개가 배열로 지정돼 있는데, 종료 토큰이 복수라는 점은 대화·툴 호출 포맷을 다루는 서빙 코드에서 직접 영향을 받는 부분입니다. 라이선스는 other이며 license_name이 glm-5.3으로 별도 명시돼 있습니다.

04어떻게 실행하거나 파인튜닝하는가

library_name이 transformers이고 클래스가 GlmMoeDsaForCausalLM이므로, 실행의 첫 관문은 사용하는 transformers 버전 또는 추론 엔진이 glm_moe_dsa를 아는지 여부입니다. 아키텍처 이름이 표준 계열과 다르다는 것은, 기존 서빙 스택에 config.json만 던져 넣는 방식이 통하지 않을 수 있다는 뜻입니다. 특히 index_topk 2048로 동작하는 인덱서 기반 희소 어텐션은 전용 커널 경로를 전제하는 부분이라, 지원 여부를 먼저 확인하는 것이 순서입니다.

리소스 관점에서는 141개 샤드와 bfloat16이 기준점입니다. 단일 가속기에 올라가는 규모를 전제로 한 워크플로가 아니며, ep_size 1로 배포된 config를 실제 병렬 배치에 맞게 바꾸는 작업이 별도로 필요합니다.

파인튜닝을 고려한다면 이 릴리스의 성격을 먼저 볼 필요가 있습니다. 카드는 GLM-5.2와 베이스가 같고 차이는 post-training에서 나왔다고 밝히고 있으므로, 추가 튜닝은 이미 상당히 다듬어진 사후 학습 결과 위에 얹는 작업이 됩니다. 코딩·에이전트 성능이 그 레시피에서 나온 것이라면, 무관한 도메인 데이터로 덧씌울 때 무엇이 깎이는지를 먼저 측정해야 합니다.

05도입 전에 확인해야 할 한계와 라이선스 조건

라이선스가 other이고 이름이 glm-5.3으로 따로 붙어 있다는 점이 가장 먼저 확인할 항목입니다. 표준 OSI 라이선스가 아니므로 상업적 사용, 재배포, 파생 모델 공개 조건을 원문에서 직접 읽어야 하며, open-weights라는 표현을 오픈소스 라이선스와 같게 취급해서는 안 됩니다.

벤치마크 수치는 모델 제공자가 낸 표에서 온 것입니다. Z.ai Code Bench는 카드가 in-house라고 명시한 자체 벤치마크이고, 나머지 공개 벤치마크 수치도 자체 측정 결과로 제시된 값입니다. 표에는 –로 비어 있는 칸이 여럿이라 모델 간 비교가 모든 항목에서 대칭적이지 않습니다.

카드가 직접 밝힌 사이버 능력은 도입 판단에서 별도로 다뤄야 하는 항목입니다. CyberGym에서의 위치와 exploitation 단계로 갈수록 GLM-5.2 대비 격차가 커진다는 서술은 성능 홍보인 동시에 배포 시 접근 통제와 사용 정책을 요구하는 조건입니다.

마지막으로 max_position_embeddings 1048576은 설정상의 상한이지 실제 품질이 그 길이까지 유지된다는 보장이 아닙니다. 인덱서 기반 희소 어텐션 구조를 감안하면, 실제 사용 길이 구간에서의 검증은 도입 측이 직접 해야 하는 몫입니다.
