한 줄 설명이 가린 것

저장소 설명은 "DeepSeek Harness: Everything is a Plugin." 한 줄입니다. README를 보면 dsh는 DeepSeek AI가 공개한 agent harness이고, Cordis 위에서 동작하며 그 설계는 arxiv 2608.25512 문서로 따로 발표돼 있습니다. 즉 이것은 에이전트 앱 하나가 아니라, 플러그인을 올려놓고 돌리는 런타임과 그 위의 Web UI입니다.

한 줄이 감추는 두 번째 사실은 상태입니다. README는 developer preview임을 명시하고 호환성을 깨는 변경이 있을 것이라고 대문자로 경고하며, 실행 전에 SAFETY.md를 읽으라고 요구합니다. 새 버전을 따라가는 비용이 처음부터 전제돼 있는 프로젝트입니다.

숫자에서도 같은 성격이 읽힙니다. 스타는 211471인데 열린 이슈는 0이고, 마지막 푸시는 2026-09-03T06:23:34Z입니다. README는 피드백과 버그 보고를 GitHub Discussions로 보내라고 안내합니다. 이슈 0은 방치가 아니라 창구를 옮겨둔 결과로 보는 편이 맞습니다.

마크다운이 코드를 앞선다

추적 파일은 8920개입니다. packages/ 아래 4506개, .agents/ 아래 2605개, snapshots/ 658개, docs/ 363개. 부피는 packages/와 .agents/ 두 곳에 몰려 있고, 사람이 읽는 문서를 담는 docs/는 오히려 snapshots/보다 작습니다.

확장자를 보면 .md 2866, .ts 2841, .yaml 1296, .json 723입니다. 주 언어는 TypeScript로 표시되는데 파일 수 1위는 마크다운입니다. 그리고 docs/가 363개뿐이므로, 마크다운의 대부분은 문서 사이트가 아니라 다른 곳에 흩어져 있다는 뜻이 됩니다.

.agents/ 2605개와 .yaml 1296개를 함께 놓으면 그림이 잡힙니다. 에이전트와 플러그인이 코드가 아니라 선언 파일과 산문으로 기술되는 구조, 그리고 snapshots/ 658개처럼 출력물을 파일로 고정해 회귀를 잡는 방식입니다. 이런 저장소에서는 기능 하나를 추가할 때 손대는 파일이 .ts 한 개로 끝나지 않습니다.

패키지가 계약을 소유한다

인용된 파일 경로 자체가 조직 단위를 보여줍니다. native/landlock-run/packages/entry/src/index.ts. 최상위 packages/ 아래만 워크스페이스인 것이 아니라, native/landlock-run이라는 하위 트리가 자기 packages/를 다시 갖고 있습니다. 네이티브 런처 하나가 독립된 패키지 가족으로 묶여 있는 셈입니다.

이 모듈의 주석은 경계를 명시합니다. 이 패키지는 prebuilt landlock-run 런처 위의 JavaScript API로서 호스트에 맞는 바이너리를 고르고 grant argv를 만들고 probe를 돌리며, 런처의 CLI 계약을 직접 소유합니다. 소비자가 런처 출력을 파싱하거나 플래그를 직접 쓰지 않게 해서, 계약과 바이너리가 한 패키지 가족 안에서 같이 버전업되도록 만든 배치입니다. 정책은 소비자 쪽에 남습니다. 이 패키지는 sandbox mode가 무엇인지 모르고, 어떤 경로가 읽기 또는 쓰기로 허용됐는지만 압니다.

환경변수 오버라이드를 의도적으로 두지 않았다는 문장도 같은 맥락입니다. 어떤 바이너리가 프로세스를 가두는지가 주변 환경에 의해 결정되면 안 되므로, 테스트 주입은 함수 파라미터로만 합니다. 노출되는 값은 런처 바이너리 이름 LAUNCHER_BIN과 실패 exit code 125이고, probe는 호스트에 대해 full, partial, unusable 세 가지 판정을 냅니다. 125는 런처 실패와 감싼 명령의 반환값이 겹칠 수 있어서, 런처가 낸 진단 메시지까지 함께 봐야 원인을 귀속할 수 있습니다.

설치 뒤에 남는 것

가장 짧은 경로는 Node.js를 설치한 뒤 npx @deepseek-ai/dsh web입니다. README에 따르면 기본값으로 http://127.0.0.1:3080 에 Web UI가 뜨고, 로컬 실행이면 기본 브라우저가 열립니다. SSH로 띄우면 호스트 URL만 출력되는데, 포워딩된 로컬 주소는 SSH 클라이언트나 에디터가 쥐고 있기 때문입니다. 브라우저를 열지 않으려면 --no-open을 씁니다.

소스 체크아웃으로 돌리려면 git clone 후 pnpm install, pnpm run build, pnpm dsh web 순서입니다. pnpm run build가 저장소 산출물을 준비하고, pnpm dsh web은 그 산출물을 다시 빌드하지 않고 씁니다.

명령이 끝나도 남는 단계가 있습니다. 실행 전에 SAFETY.md를 읽으라는 요구가 README 본문에 있고, everything-is-a-plugin 구조인 이상 무엇을 올릴지는 설치와 별개의 결정입니다. 샌드박스 쪽도 마찬가지입니다. probe 판정이 unusable이면 아무것도 강제되지 않는 상태이므로, 켜졌는지 여부는 설치가 아니라 호스트 커널이 정합니다.

도입을 막는 조건

라이선스는 MIT이고 서드파티 의존성과 그 라이선스는 THIRD_PARTY_NOTICES.md에 따로 공개돼 있습니다. 라이선스 자체는 걸림돌이 아닙니다.

걸리는 것은 상태와 적용 범위입니다. developer preview이며 호환성을 깨는 변경이 예고돼 있으니, 고정 버전으로 묶고 업그레이드마다 확인하는 비용을 계산해야 합니다. 격리를 기대한다면 landlock-run이 무엇인지 먼저 봐야 합니다. probe는 커널이 런처가 다룰 수 있는 모든 접근을 강제할 때 full, 오래된 Landlock ABI가 일부만 다룰 때 partial, 아무것도 강제할 수 없을 때 unusable을 냅니다. partial도 지원하는 범위 안에서는 가둔 상태지만, unusable이면 격리는 없습니다.

운영 비용은 파일 모양에서 그대로 나옵니다. .yaml 1296개와 .json 723개, .agents/ 2605개는 설정과 선언이 코드와 맞먹는 유지 대상이라는 뜻입니다. 지원 창구는 이슈 트래커가 아니라 GitHub Discussions와 Discord이고, 사내에서 쓰다 막혔을 때 답이 돌아오는 속도도 그 채널에 달려 있습니다.
