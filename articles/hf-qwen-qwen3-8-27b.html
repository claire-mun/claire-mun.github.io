Qwen3.8-27B: 이름은 3.8이지만 config는 qwen3_5인 27B 비전-언어 dense 모델

2026년 09월 01일 · 출처 3곳

Qwen3.8-27B는 transformers 포맷으로 배포된 image-text-to-text 모델로, 27B dense 언어 모델에 비전 인코더가 붙어 있고 linear attention과 full attention을 섞은 층 구조를 씁니다. 자체 호스팅으로 멀티모달 추론을 돌리거나 기존 vLLM/SGLang 서빙 스택에 새 체크포인트를 얹으려는 엔지니어에게 해당됩니다.

01이 모델이 무엇인가

저장소가 선언하는 태스크는 image-text-to-text, 라이브러리는 transformers입니다. 아키텍처 클래스는 Qwen3_5ForConditionalGeneration이고 model_type은 qwen3_5입니다. 즉 이름은 Qwen3.8이지만 모델링 코드 관점에서는 Qwen3.5 계열 구현을 그대로 탑니다. 모델 카드도 "Built on the architectural foundation of Qwen3.5"라고 밝히고 있어, config가 이 서술과 일치합니다.

config.json의 language_model_only는 false입니다. 이 체크포인트는 언어 모델만 떼어낸 판본이 아니라 비전 경로가 살아 있는 판본이라는 뜻이고, image_token_id로 248056이 지정돼 있습니다. 모델 카드의 Model Overview는 타입을 Causal Language Model with Vision Encoder, 언어 모델 파라미터 수를 27B, hidden dimension을 5120으로 적고 있으며 text_config의 hidden_size 5120이 여기에 대응합니다.

text_config의 나머지 값은 dense 트랜스포머의 평범한 구성입니다. intermediate_size 17408, head_dim 256, hidden_act는 silu, attention_bias는 false, attention_dropout은 0.0, dtype은 bfloat16입니다. 눈에 띄는 항목은 attn_output_gate가 true라는 점으로, 어텐션 출력에 게이트가 붙는 변형을 쓴다는 신호입니다.

구조에서 가장 중요한 부분은 layer_types 배열입니다. linear_attention이 세 개 이어진 뒤 full_attention이 하나 오는 패턴이 반복되고, 이는 별도 필드인 full_attention_interval 4와 정확히 맞물립니다. 전체 층 중 네 층에 한 층만 full attention이므로, KV 캐시가 필요한 층도 그 비율로만 존재합니다. 긴 컨텍스트를 다룰 때 메모리 곡선이 순수 full attention 모델과 다르게 움직이는 이유가 여기에 있습니다.

02지금 트렌딩에 오른 이유

수치 자체가 큽니다. 최근 30일 다운로드는 4960483, 좋아요는 13668입니다. 마지막 수정 시각은 2026-08-14T15:00:01.000Z입니다.

태그 구성도 이 모델이 실험용이 아니라 배포 경로를 전제로 올라왔음을 보여줍니다. 선언된 태그에 endpoints_compatible, deploy:azure, deploy:sagemaker, eval-results가 들어 있습니다. 관리형 엔드포인트와 두 클라우드의 배포 경로가 태그 수준에서 이미 잡혀 있다는 뜻입니다.

채택 속도를 설명하는 구조적 요인은 앞서 본 model_type qwen3_5입니다. 새 세대 이름을 달았지만 로더 입장에서는 이미 지원하는 아키텍처이므로, 런타임이 qwen3_5를 알고 있다면 별도 모델링 코드 없이 붙습니다. 모델 카드도 아티팩트가 Hugging Face Transformers, vLLM, SGLang, TokenSpeed 등과 호환된다고 명시합니다.

카드가 내세우는 변화는 코딩, 전문 업무, 리서치, 장기 에이전트 태스크 전반의 개선, 환경 피드백 처리와 자율 계획 강화, 그리고 thinking 제어입니다. thinking 모드는 기본으로 켜져 있고 요청 단위로 끌 수 있으며, reasoning_effort로 깊이를 조절하고 preserve_thinking으로 과거 메시지의 추론 컨텍스트를 유지합니다.

03실제로 무엇이 들어 있나 (가중치, config, 라이선스)

저장소 파일은 32개이고 그중 가중치 샤드가 18개입니다. 나머지 열몇 개가 config, 토크나이저, 인덱스, 카드류라는 뜻이므로 이 리포지토리는 사실상 가중치 덩어리입니다. 샤드가 18개로 쪼개져 있으니 다운로드 재개와 샤드 단위 로딩이 가능하지만, 그만큼 인덱스 파일과 실제 샤드의 정합성이 깨지면 로드가 통째로 실패합니다.

가중치 dtype은 config에 bfloat16으로 선언돼 있습니다. 여기 주어진 자료에는 양자화 판본에 대한 언급이 없으므로, 이 리포지토리 자체는 bf16 체크포인트로 보고 계획을 세우는 편이 맞습니다.

토큰 id는 한 가지 확인할 점을 남깁니다. bos_token_id와 eos_token_id가 둘 다 248044로 같고, image_token_id는 248056입니다. bos와 eos가 동일한 id인 구성은 채팅 템플릿이 경계 토큰을 다루는 방식에 의존하므로, 직접 프롬프트를 조립할 때 종료 조건 판정을 이 id 하나로만 걸면 예상과 다르게 동작할 수 있습니다.

라이선스는 apache-2.0이고, 모델 카드 front matter에도 license: apache-2.0으로 동일하게 적혀 있습니다.

04어떻게 실행하거나 파인튜닝하는가

모델 카드는 이 아티팩트가 Hugging Face Transformers, vLLM, SGLang, TokenSpeed 등과 호환된다고 적고 있습니다. 실무에서 첫 관문은 버전입니다. config가 요구하는 것은 model_type qwen3_5와 Qwen3_5ForConditionalGeneration이므로, 설치된 transformers 또는 서빙 런타임이 이 model_type을 아는 빌드여야 합니다. 모델 이름의 3.8을 기준으로 지원 여부를 판단하면 어긋납니다.

두 번째는 어텐션 구현입니다. layer_types가 linear_attention과 full_attention을 섞고 있어서, 런타임이 linear attention 경로를 지원하는지가 성능과 정확성 양쪽에 걸립니다. 일반적인 full attention 커널 최적화 옵션만 켜 놓고 기대한 처리량이 나오는지 판단해서는 안 되는 구성입니다.

세 번째는 thinking 관련 파라미터입니다. thinking 모드는 기본으로 켜져 있으므로 별도 조치 없이 호출하면 추론 출력이 포함된 형태가 기본값입니다. 요청 단위 비활성화, reasoning_effort, preserve_thinking은 요청 파라미터와 템플릿 수준의 기능이라 이를 이해하지 못하는 하네스에서는 조용히 무시될 수 있습니다. 파이프라인이 이 필드를 실제로 전달하는지 확인하는 편이 안전합니다.

파인튜닝 쪽에서는 language_model_only가 false라는 점이 설계 결정을 하나 강제합니다. 비전 경로가 포함된 체크포인트이므로, 텍스트 태스크만 학습시킬 계획이라면 비전 인코더를 어떻게 처리할지(동결할지, 학습 대상에서 뺄지)를 명시적으로 정해야 합니다. attention_dropout이 0.0이고 initializer_range가 0.02인 것도 참고할 값으로, 드롭아웃 기반 정규화는 기본 config에 들어 있지 않습니다.

05도입 전에 확인해야 할 한계와 라이선스 조건

라이선스는 apache-2.0입니다. 여기 주어진 자료 범위에서는 별도의 사용 정책 문서나 추가 제약이 언급돼 있지 않으므로, 조건은 Apache-2.0 표준 조항 그대로 검토하면 됩니다.

컨텍스트 길이는 오해하기 쉬운 지점입니다. 모델 카드가 언급하는 1M context length by default는 Qwen Cloud의 호스팅 버전에 대한 서술이고, 그 서비스는 카드 본문에서 coming soon 상태라고 밝히고 있습니다. 여기 제시된 config.json 발췌에는 컨텍스트 길이 필드가 포함돼 있지 않으므로, 자체 호스팅에서 실제로 몇 토큰까지 잡히는지는 리포지토리의 전체 config를 직접 확인해야 합니다. 호스팅 서비스의 숫자를 로컬 배포 계획의 전제로 삼으면 안 됩니다.

아키텍처 이름과 모델 이름의 불일치는 운영 문제로 번질 수 있습니다. 모델 카드 제목과 저장소 이름은 Qwen3.8-27B인데 model_type은 qwen3_5입니다. 모델 이름 문자열로 라우팅하거나 지원 목록을 관리하는 내부 툴링이 있다면 이 체크포인트를 잘못 분류할 여지가 있습니다.

성능 근거도 확인이 필요합니다. 태그에 eval-results가 있지만, 여기 주어진 발췌에는 벤치마크 수치가 포함돼 있지 않습니다. 카드가 말하는 개선은 코딩, 전문 업무, 리서치, 장기 에이전트 태스크 전반이라는 서술 수준이므로, 자체 태스크에서의 판단은 직접 평가해서 내려야 합니다.
