0.504와 0.184를 가른 것은 압축률이 아니라 표현 형식

2026년 09월 04일 · 출처 2곳

LongMemEval에서 7.70배 압축한 continuous memory token이 0.504로 무압축 근거의 0.490을 넘는데, 같은 내용을 텍스트 요약으로 옮기면 0.184로 떨어집니다.

텍스트 복원 없는 읽기

논문의 주장은 하나로 좁혀집니다. 압축된 대화 이력과 긴 문서를 continuous memory token으로 쓰고, frozen decoder가 그것을 input-embedding 인터페이스로 직접 읽으며, 추론 시점에 텍스트 복원 단계가 없다는 것입니다.

숫자로 보면 이렇습니다. LongMemEval에서 7.70배 압축 상태의 정확도가 0.504, 압축하지 않은 근거를 그대로 넣었을 때가 0.490입니다. 텍스트 요약은 0.184, OCR 기반 압축은 0.426에서 0.312 사이입니다.

여기서 눈에 띄는 것은 압축과 무압축의 간격이 아닙니다. 0.504와 0.184의 간격입니다. 같은 정보를 어떤 형식으로 운반하느냐가, 얼마나 줄이느냐보다 결과를 크게 흔들었다는 뜻입니다.

사람이 읽을 필요가 없는 컨텍스트

초록이 지목하는 문제 설정은 단순합니다. 압축된 컨텍스트는 보통 사람이 읽을 수 있는 텍스트이거나, 다시 디코딩해야 하는 렌더링된 이미지 형태로 운반됩니다. 그런데 그것을 최종적으로 소비하는 쪽은 언어 모델입니다.

소비자가 모델인데도 사람이 읽는 형식을 거치면 두 가지 비용이 붙습니다. 정보 손실과 디코딩 시간입니다. 텍스트 요약 0.184와 OCR의 0.426에서 0.312라는 수치가 앞쪽 비용에 해당합니다.

학습하는 부분은 어댑터뿐

구조에서 결정적인 지점은 학습 범위입니다. 디코더는 얼려두고, reader-matched writer 쪽 adapter만 학습합니다. 그 adapter는 4.2M에서 26.2M 파라미터로, 디코더의 약 0.1퍼센트 규모라고 적혀 있습니다.

즉 디코더의 가중치를 건드리지 않고, 입력 임베딩이라는 이미 존재하는 인터페이스에 맞춰 쓰는 쪽만 조정합니다. 압축 배율은 4배에서 16배 범위로 제시됩니다.

writer가 reader에 맞춰져 있다는 점은 성능의 근거이면서 동시에 제약입니다. 뒤에서 다시 걸립니다.

두 벤치마크와 두 전이

확인한 범위는 벤치마크 두 개와 전이 설정 두 개입니다. LongMemEval에서는 앞서 본 수치가 나오고, LongBench-QA에서는 in-domain writer가 4배에서 8배 압축 구간에서 raw context 읽기와 같거나 그보다 낫다고 보고합니다. 전이는 UltraChat에서 LongMemEval memory QA로 가는 zero-shot, 그리고 LongMemEval에서 유도한 QA에서 처음 보는 LongBench 문서 도메인으로 가는 설정입니다.

확인되지 않은 쪽도 초록 안에 적혀 있습니다. LongBench-QA에서 16배는 raw에 못 미칩니다. 압축 배율을 올리는 것이 공짜가 아니라는 경계가 그 지점에 있습니다.

속도는 별도로 보고됩니다. 쓰기는 대화 하나당 43ms로 텍스트 요약이나 OCR 복원보다 대략 한 자릿수 빠르고, 읽기는 raw context나 캐시된 OCR보다 5배에서 9배 빠릅니다. 저자는 2명, cs.LG 분류, 2026-09-01 공개 후 2026-09-03에 v2로 갱신됐습니다.

writer는 디코더에 묶인다

실무로 옮길 때 먼저 걸리는 것은 reader-matched라는 조건입니다. writer가 특정 디코더의 입력 임베딩에 맞춰 학습되므로, 읽는 모델을 바꾸면 그 어댑터를 다시 확보해야 합니다. 학습 대상이 4.2M에서 26.2M 파라미터로 작다는 점이 이 재작업의 부담을 낮추는 방향으로 작용합니다.

두 번째는 배율 선택입니다. LongBench-QA 기준으로 4배에서 8배는 raw와 대등하거나 낫지만 16배는 뒤처집니다. 저장 비용을 어디까지 밀지는 이 경계 안에서 결정할 문제입니다.

세 번째는 저장물의 성격입니다. 압축 결과가 텍스트가 아니라 continuous memory token이므로, 사람이 열어서 확인하는 감사나 디버깅 경로는 텍스트 요약을 쓰던 때와 달라집니다. 구현은 github.com/HJSang/LatentPress에 공개돼 있다고 초록에 적혀 있습니다.
